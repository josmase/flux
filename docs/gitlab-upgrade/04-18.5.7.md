## Required manifest change

Update the GitLab chart target from `9.2.8` to `9.5.7`. The pre-window
database-bootstrap change creates `amcheck` in the Rails database. Do not
change the database host, generated DB Secrets, Valkey endpoint, repository
PVC, or ingress model in the same stop. Chart `9.5.7` removes the legacy
`certmanager.install` value; retain the disabled bundled cert-manager by using
the supported top-level `installCertmanager: false` value.

## Window procedure

Follow Sections 2–5 of the operating standard. The version-specific order is:

1. Suspend `apps-gitlab` and the GitLab HelmRelease; record the deployed Helm
   revision and Flux source revision.
2. Stop writers only after the verified dumps are complete.
3. Apply the rendered `9.5.7` values manually with a recorded timeout. Treat
   a migration Job failure or a Gitaly attach failure as a stop condition.
4. Wait for the migrations, then restore writers.
5. Verify web health, Gitaly, Registry read/write, Git SSH/HTTP access, a
   runner job, and `gitlab:background_migrations:status`.
6. Push the accepted version commit and resume Flux only after all checks
   pass; verify the complete Flux chain is Ready at that revision.
