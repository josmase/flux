# Stop 6: GitLab 19.2.10 / chart 10.2.10

**Theme:** Major chart transition and Registry `s3_v2` activation.
**Risk:** High. Chart 10 removes bundled components and changes defaults; this
is not a routine patch upgrade.
**Window:** Suspended manual window with explicit rollback decision points.

Use the mandatory [operating standard](11-operational-standard.md).

## Stop-specific preflight

- [ ] Stop 5 is accepted, with no blocking standard or background migrations.
- [ ] A reviewed `9.11.16 → 10.2.10` rendered-manifest diff is attached to the
  change record. It lists every Service, StatefulSet, PVC, Job, ingress, CRD,
  and Secret-reference change.
- [ ] The render proves bundled PostgreSQL, Redis, MinIO, chart ingress,
  Gateway API, and Envoy are not enabled. It preserves dedicated CNPG,
  dedicated Valkey, Gitaly persistence, and Traefik routes.
- [ ] Registry `s3_v2` configuration is staged as an encrypted Secret and
  reviewed. Test the actual RustFS backend before the window with push, pull,
  tag delete, and log inspection. Stop if `DeleteObjects`, checksum, or path
  style behaviour fails.
- [ ] Legacy data PVCs are inventoried and protected. Chart 10 removal of a
  bundled workload never authorizes deletion of its PVC or LINSTOR resource.
- [ ] Fresh verified Rails/Registry dumps and an explicit Stop 5 rollback path
  are available off-cluster.

## Required manifest changes

1. Update chart `9.11.16` to `10.2.10`.
2. Keep `global.gatewayApi.enabled: false`, Envoy installation disabled,
   NGINX/chart ingress disabled, and Traefik as the only public route.
3. Preserve external PostgreSQL and Valkey references exactly; chart-key names
   may retain Redis compatibility terminology, but the live endpoint remains
   `gitlab-valkey.gitlab.svc`.
4. Switch Registry storage only to the reviewed `s3_v2` Secret configuration.
   Do not change bucket, identity, or prefix in the same window.

## Window procedure

1. Follow the operating standard through verified dumps and writer shutdown.
2. Apply the reviewed chart-10 render manually. Do not use an automatic Helm
   rollback after Rails/Registry migrations begin; pause for an explicit
   recovery decision instead.
3. Confirm that Gitaly, CNPG, and Valkey remain attached and Ready before
   restoring writers.
4. Restore webservice first; validate GitLab health and database/cache access.
   Restore Registry next and complete the `s3_v2` functional tests before
   restoring the remaining writers.
5. Only then complete user-path checks and the Flux handoff.

## Acceptance criteria

| Check | Expected evidence |
| --- | --- |
| Major-version state | GitLab `19.2.10-ee`, chart `10.2.10`, Helm release deployed, Flux HelmRelease Ready. |
| Removed chart components | No chart-managed bundled PostgreSQL/Redis/MinIO workload is recreated; retained rollback PVCs remain intact and are not mounted accidentally. |
| External services | CNPG and Valkey are Ready; generated database credential connections pass. |
| Registry | Push, pull, tag delete, and registry-log review pass using `s3_v2`. |
| Repository data | Gitaly device path/replica health and `gitlab:gitaly:check` pass; disposable clone/push succeeds. |
| Networking | Traefik external IP, Service endpoints, and GitLab routed health are healthy. |
| GitOps | The complete Flux chain converges at the accepted commit. |

## Rollback boundary

If chart-10 acceptance fails before an irreversible data transition, restore the
recorded Stop 5 configuration with writers stopped. Keep all old PVCs and the
pre-stop Secrets. If Registry `s3_v2` fails, revert only after preserving the
failure logs and confirming the legacy driver configuration can still read the
same data. Database restore requires the verified Stop 6 dumps and an explicit
incident decision.

## Change record additions

Include the rendered-diff inventory, PVC inventory, `s3_v2` test transcript,
Registry logs, Gitaly/LINSTOR evidence, dump hashes, and Flux convergence
evidence.
