This replaces the failed shared-CNPG/manual-Helm attempt. It is a controlled
reinstall of GitLab 18.2.8 / chart 9.2.8 from the approved logical dumps.

## Bootstrap order

1. Apply `apps-gitlab-bootstrap`; wait for `gitlab-postgres` (three Ready
   instances), its services, and authenticated `gitlab-valkey`.
2. Apply `apps-gitlab-db-bootstrap`; wait for `gitlab-db-init-stop2` and
   `registry-db-init-stop2`. The deliberately renamed Jobs do not reuse the
   stuck prior Stop 2 Job templates. They generate `gitlab-external-db` and
   `gitlab-registry-external-db`; do not create or edit these Secrets manually.
3. Before starting GitLab, restore the dumps with PostgreSQL 17.2 tooling and
   make failures terminal:

   ```sh
   pg_restore --exit-on-error --no-owner --no-privileges --role=gitlab \
     --dbname=gitlabhq_production gitlabhq_production_2026-11-01_2005.dump
   pg_restore --exit-on-error --no-owner --no-privileges --role=registry \
     --dbname=registry registry_2026-11-01_2005.dump
   ```

   Run the commands through an authenticated PostgreSQL 17.2 client. Do not
   pre-create `btree_gist` or `pg_trgm`: Rails dump metadata creates both
   extensions. The provisioner creates only `pgcrypto`, which is absent from
   the validated dump metadata and is required by current GitLab migrations.
4. Verify table counts, extensions, object ownership, and application-role
   connectivity. Create and verify a dedicated CNPG backup.
5. If an immutable Gitaly StatefulSet field blocks Helm, remove only the
   obsolete StatefulSet with orphaned PVC retention after confirming that
   `repo-data-gitlab-gitaly-0` remains Bound. Never delete the repository PVC.
   Then apply the rendered chart 9.2.8 values from the local emergency branch.
6. Complete migrations and application acceptance. The committed
   `apps-gitlab` Kustomization is intentionally suspended, so neither applying
   the bootstrap Kustomizations nor recovering the Flux source can race this
   step. In a follow-up commit, set `apps-gitlab.spec.suspend: false`, push it
   to recovered GitLab, and then reconcile Flux.

## Hard gates

- `gitlab-postgres-rw.gitlab.svc` is the only PostgreSQL host used by GitLab.
- `gitlab-valkey.gitlab.svc` requires authentication; unauthenticated PING
  must fail and an AOF-persisted test key must survive a controlled restart.
- The restore must finish with no `pg_restore` errors. The `gitlab` and
  `registry` roles must own their restored objects; do not restore as
  `postgres` and attempt to repair ownership later.
- Chart-managed ingress is disabled. Traefik IngressRoutes remain the only
  public route.
- Do not consider Flux recovered until its GitRepository fetch and
  `infra-configs` are both Ready.
