## Required manifest change

After the Runner prerequisite is accepted, update chart `9.5.7` to `9.8.12`
only. The existing dedicated `gitlab-valkey`
StatefulSet and auth Secret are production dependencies, not temporary setup
objects. Do not create an alternative standalone Valkey, change namespaces, or
delete a legacy PVC during this stop.

## Window procedure

Push the rendered and validated server commit while GitLab is healthy, verify
it with `git ls-remote`, then reconcile the Flux source/dependency chain and
`apps-gitlab`. Monitor Helm history, HelmRelease conditions, migration Jobs,
Kubernetes events, and API readiness throughout. If a Helm attempt fails
before migrations start because of a transient API transport error, verify API
readiness and retry the declarative HelmRelease; do not roll back solely for
that failed pre-upgrade attempt.

## Rollback boundary

Rollback to the recorded Stop 3 chart and Git commit before accepting a failed
migration. Preserve the dedicated Valkey PVC and auth Secret: they are not a
rollback disposable. Restore a database only from the verified stop dump when
the database state—not merely the application chart—is the failure.
