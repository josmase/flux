## 🎯 Stop 1 Learnings (Applied to This Stop)

| Issue | Impact | Fix | Prevention |
|-------|--------|-----|------------|
| Missing `postgresql-postgres-password` secret key | Pre-upgrade hook fails, upgrade aborts | Patch secret with both keys | Check both keys exist before every stop |
| Metrics sidecar images not in local registry | `ImagePullBackOff`, pods not ready | Disable `postgresql.metrics.enabled` and `redis.metrics.enabled` | Check image availability at every stop |
| HelmRelease `RetriesExceeded` / `Stalled` | Flux won't retry upgrade | Delete HelmRelease: `kubectl -n gitlab delete helmrelease gitlab` | Monitor reconciliation closely |
| GitLab down (503) — `git push` fails | Can't push fixes to git | Suspend Flux, apply manual `kubectl` patches, resume when GitLab recovers | Suspend Flux before manual changes |
| `sudo` blocked in toolbox container | `gitlab-rake` fails | Run `gitlab-rake` directly without `sudo` | Never use `sudo` in toolbox |
| Pending DB migrations block app startup | Webservice/Sidekiq CrashLoopBackOff | Run `rake db:migrate` via toolbox before scaling up | Check migration status before scale-up |

### Phase 3: Final Dumps (Bundled PG) — ✅ COMPLETED

```bash
# Port-forward to bundled PG
kubectl -n gitlab port-forward svc/gitlab-postgresql-hl 5432:5432 &
PID=$!; sleep 2

# Dump gitlabhq_production
PGPASSWORD=$(kubectl -n gitlab get secret gitlab-postgres-password -o jsonpath='{.data.postgres-password}' | base64 -d)
docker run --rm --network host -e PGPASSWORD="$PGPASSWORD" postgres:17.2 \
  pg_dump -h 127.0.0.1 -p 5432 -U postgres -d gitlabhq_production \
  --no-owner --no-privileges --exclude-extension='*' \
  --format=custom > gitlabhq_production_final_$(date +%F_%H%M).dump

# Dump registry
REG_PW=$(kubectl -n gitlab get secret gitlab-registry-database-password -o jsonpath='{.data.password}' | base64 -d)
docker run --rm --network host -e PGPASSWORD="$REG_PW" postgres:17.2 \
  pg_dump -h 127.0.0.1 -p 5432 -U registry -d registry \
  --no-owner --no-privileges --exclude-extension='*' \
  --format=custom > registry_final_$(date +%F_%H%M).dump

# Checksums
sha256sum *_final_*.dump > dumps_final_$(date +%F_%H%M).sha256
kill $PID
```

**Dump files created:**
- `/tmp/gitlabhq_production_dump_2026-11-02_0213.dump` (17M)
- `/tmp/registry_dump_2026-11-02_0214.dump` (3.2M)

**Note**: Port-forward to bundled PG is unstable — may need to restart between commands.

### Phase 4: Restore into CNPG — ⚠️ IN PROGRESS (Partial)

```bash
# Port-forward CNPG (to pod directly for stability)
kubectl -n cnpg-system port-forward pod/shared-postgres-12 5433:5432 &
PID_CNPG=$!; sleep 2

SUPER_PW=$(kubectl -n cnpg-system get secret shared-postgres-superuser -o jsonpath='{.data.password}' | base64 -d)

# Restore gitlabhq_production
docker run --rm --network host -e PGPASSWORD="$SUPER_PW" -i postgres:17.2 \
  pg_restore -h 127.0.0.1 -p 5433 -U postgres -d gitlabhq_production \
  --no-owner --no-privileges --clean --if-exists \
  < gitlabhq_production_final_*.dump

# Restore registry
docker run --rm --network host -e PGPASSWORD="$SUPER_PW" -i postgres:17.2 \
  pg_restore -h 127.0.0.1 -p 5433 -U postgres -d registry \
  --no-owner --no-privileges --clean --if-exists \
  < registry_final_*.dump

kill $PID_CNPG
```

**Restore status:**
- `gitlabhq_production`: Partially restored (~39 projects loaded before port-forward dropped). Extensions `plpgsql`, `pg_trgm`, `btree_gist` pre-created.
- `registry`: Not yet restored.

**Known issue**: `kubectl port-forward` to CNPG drops connection mid-restore for large dumps (17M gitlabhq_production). Workaround: restart port-forward and re-run `pg_restore` (it's idempotent with `--clean --if-exists`).

**Extensions pre-created** (required for `pg_trgm`/`gin` indexes and `btree_gist` exclude constraints):
- `gitlabhq_production`: `plpgsql`, `pg_trgm`, `btree_gist`
- `registry`: `plpgsql`

**CNPG superuser**: `enableSuperuserAccess: true` set durably via Flux in `infrastructure/base/configs/cloudnative-pg/cluster.yaml`.

> **Note**: CNPG port-forward is unstable — drops connection mid-restore. Restart port-forward and re-run `pg_restore` until complete. The restore is idempotent (`--clean --if-exists`).
