# Stop 5: GitLab 18.11.14 / chart 9.11.16

**Theme:** Final 18.x compatibility and readiness stop before the chart-10
transition.
**Risk:** Medium; this stop is deliberately narrow so that chart-10 changes
are isolated in Stop 6.
**Window:** Suspended manual window.

Use the mandatory [operating standard](11-operational-standard.md).

## Stop-specific preflight

- [ ] Stop 4 is accepted; all prior background migrations are complete.
- [ ] Dedicated CNPG is PostgreSQL 17 and has backup/capacity evidence. Do not
  upgrade PostgreSQL in this application stop.
- [ ] Dedicated Valkey, Gitaly, Registry, Traefik routes, and Flux dependency
  chain are all Ready.
- [ ] The `9.11.16` render is reviewed against `9.8.12`; it retains external
  PostgreSQL/Valkey, disabled chart ingress, and all Gitaly persistence.
- [ ] The chart-10 render is prepared and reviewed separately, but it is not
  committed to or applied by the Stop 5 release branch. This prevents a
  “validation” stop from smuggling in a major chart transition.

## Required manifest change

Update chart `9.8.12` to `9.11.16` only. Keep the current dedicated-service
configuration unchanged.

## Window procedure and acceptance

Follow the operating standard. This stop is accepted only after:

| Check | Expected evidence |
| --- | --- |
| Version | GitLab `18.11.14-ee`, chart `9.11.16`, and a deployed Helm revision. |
| Core services | Web, Sidekiq, KAS, Shell, Registry, Toolbox, Gitaly, CNPG, and Valkey are Ready. |
| Database | Application roles connect to `gitlab-postgres-rw.gitlab.svc`; migrations and background migrations have no blocking failures. |
| Storage | Gitaly’s DRBD volume has a device path and all replicas are `UpToDate`; Gitaly check passes. |
| Public paths | Git clone/push, Registry push/pull, runner job, and Traefik-routed health check pass. |
| GitOps | Every dependency Kustomization and HelmRelease is Ready at the pushed revision. |

## Chart-10 preparation after acceptance

Create a separate review artifact for Stop 6 that compares the `9.11.16` and
`10.2.10` renders. The review must enumerate every removed/added Service,
StatefulSet, PVC reference, CRD, ingress, Secret reference, and Registry
storage configuration. No destructive resource deletion is authorized by this
preparation step.

## Rollback boundary

Return to the recorded Stop 4 Helm release and Git commit while writers are
stopped. Preserve all dedicated data and legacy rollback PVCs. If data must be
restored, use the Stop 5 dump only after recording why a chart rollback is
insufficient.

## Change record additions

Attach the chart-10 render review separately from Stop 5 acceptance, along
with dump hashes, Helm/Flux revisions, storage evidence, and test results.
