## Source-matched baseline restore rehearsals — live evidence (2026-11-13)

The obsolete bootstrap Job/ConfigMap precondition was replaced in `utility-scripts/cluster/linstor-v2-workload-restore.py` with an exact T3.6 baseline-manifest check and a uniquely matched restorable full RustFS backup. The helper verifies source handle and snapshot ID, performs an independent S3 download to a dedicated scratch LINSTOR resource, uses a deny-all network policy and read-only PVC mount, then confirms the production replica inventory and remote backup key set are unchanged before removing only isolated scratch resources. For SQLite workloads it streams only `config.xml` and database files to a private temporary directory; database bytes are not committed.

Six sources passed directly: Sonarr-1, Sonarr-2, Sonarr-4, Sonarr-6, Prowlarr, and the prior Arr Dashboard isolated T3.4 checksum restore. Neither repair altered the restored PVC, source PVC, or backup. The [Sonarr recovery guidance](https://wiki.servarr.com/sonarr/faq#help-my-database-is-corrupt) documents the `logs.db` recovery path. Application boot validation remains in T7.
